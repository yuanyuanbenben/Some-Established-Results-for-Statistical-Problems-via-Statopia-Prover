# Reproduction with selected Statlib dependencies

The original archived proof sources are unchanged. `minimal-sources/` contains derivatives with narrowed imports and redundant `open _root_.Statlib` scaffold lines removed. All other nonblank lines, including theorem statements, definitions and proof bodies, are preserved. `minimization.json` maps originals to derivatives and records hashes and candidate-build results. Historical measurements still describe the originals.

`statlib-cache/` is an ordinary directory populated from the derivatives' actual imports plus the neural-network public endpoint. `binary-manifest.json` records every included compiled module, its imports and artifact hashes. It contains no Statlib source. The selected closure excludes the broad `Statlib` umbrella module. This is a transitive module dependency subset; it does not claim a globally smallest proof-term encoding.

The exact Lean toolchain and Mathlib revision are recorded in `lean-toolchain`, `lakefile.toml` and the binary manifest. A cache is compatible only with matching versions. The cache reflects the current compiled library, not a reconstruction of every historical dependency revision, nor a fresh build of the hidden Statlib sources.

To reproduce, run `make setup` followed by `make verify` in the project root. The root `lean-toolchain`, `lakefile.toml` and `lake-manifest.json` pin public dependencies. The verification script validates the complete loose-file cache inventory and every binary hash, rejects Statlib/StatAssist/ProverJobs fallback paths, compiles the derivatives into separate temporary case directories, and writes `verification/clean-build.json`. Alternatively, use `python3 scripts/verify_minimal.py --mathlib-project /absolute/path/to/a/compatible/project --workers 12`. Plain `lake build` is not the full verification gate: case projects intentionally retain separate module namespaces, including multiple `Main` entries. This procedure requires Python 3.12+ and the recorded Lean toolchain. Current validation is on Linux; other platforms have not been tested.

One additional source repair is explicitly recorded: the raw reconstructed BH-FDR Dobriban endpoint included English YAML proof instructions as executable tactic text. Its derivative comments out those instructions and example alternatives while preserving the actual proof. All other permitted source changes concern imports and unused root-namespace openings.

Recompiling public `.lean` files against supplied binary dependencies checks the public proof source in that supplied environment. To recheck compiled proof terms as well, use the matching toolchain's `leanchecker --fresh Module.Name`. Without `--fresh`, only the selected module's new declarations are replayed and its imported environment is trusted. Check the entire required dependency closure, not just one final file, and inspect `#print axioms` for every public target. The checker also accepts declared axioms: replay success does not establish that a retained citation assumption has been proved.

An axiom report alone does not check that hidden definitions mean what the paper says. Compare the exported statement and relevant definitions with the question/paper, especially for the neural-network endpoint. Providing `.olean` does not preserve source confidentiality at the level of declarations and proof terms.

Run `make replay` (or `python3 scripts/replay_cache.py --mathlib-project /absolute/path/to/a/compatible/project`) to recheck the supplied library declarations over the pinned public Mathlib/Lean environment. `kernel-replay.json` and `kernel-replay.log` record the result: eligible safe, non-partial declarations are checked; unsafe/partial runtime helpers are listed as skipped, and declared axioms are admitted rather than proved. The final-target axiom inspection separately rejects any unlisted assumptions or `sorryAx`. Public Mathlib/Lean itself is trusted in this replay and is not rebuilt or replayed by this check.

Some declarations recorded as retained in historical paper manifests may be unused by the final root. `clean-build.json` distinguishes the retained set from actual recursive root dependencies. If `--resume` is used, the original clean-compilation receipts are hash-bound and retained; the report records their original workspace and report hash. Resuming boundary checks does not claim a second full source recompilation.

Official references: [Lean compilation and kernel checking](https://lean-lang.org/doc/reference/latest/Elaboration-and-Compilation/) and [built-in leanchecker instructions](https://github.com/leanprover/lean4checker#using-the-built-in-leanchecker).

`materials.json` records paper-PDF provenance. Data Thinning and EILLS PDFs were already compiled from byte-identical copies of the archived TeX. HMC's original v5 PDF includes its corrigendum in Appendix D. The original Gaussian and neural reference PDFs are the reading copies. Redundant local build previews and their rendering diagnostics were moved outside this project during cleanup.

The directory layout replaces the former generated delivery archives without changing any binary or proof-source bytes. `directory-layout.json` records the cache location and local-only private-source relocations. To preserve the hash binding of prior compilation receipts, `binary-manifest.json` remains byte-identical: its `archive*` fields are historical metadata, while the per-module `files` records are authoritative and checked against `statlib-cache/`. No archive is read by either verification command. `clean-build-before-directory-layout.json` preserves the pre-migration receipt report. The layout check reuses hash-matched case receipts and freshly compiles/checks the neural wrapper; it does not claim another full case recompilation.

Only runtime verification tools remain in `scripts/`: case indexing, binary hashing, source compilation, axiom inspection and kernel replay. One-time collection, minimization and report-generation tools were moved outside the project. The index/import functions were preserved exactly and compared for all 96 cases and 753 derived modules. See [cleanup records](cleanup.json).

The seven neural-network implementation modules are now published under [Statlib/](../statlib-contributions/neural-network-approximation/Statlib/) with hashes from their original `metrics.json`. Other Statlib source is not included. The existing proof-verification and kernel-replay receipts continue to describe the binary-based procedure; this source publication does not claim a new rebuild of all seven modules.
